# bench —— 三条路线的公共评测基准

三条技术路线如果各自用各自的素材做演示，产出的数字不可比，选型就没有依据。
本目录提供一份**时间轴完全已知**的输入和一套统一的打分口径，让三条路线在同一把尺子下对比。

## 它评什么，不评什么

| 评 | 不评 |
|---|---|
| 告警延迟：违规发生到首次告警几秒 | 感知模型在真实人脸/人体上的精度 |
| 误报率：干扰动作是否被误判为违规 | 夜间、逆光、戴口罩墨镜等真实工况鲁棒性 |
| 检出率：标注区间是否被覆盖 | 不同人种、体型、车型的泛化 |
| 事件语义：三条路线产出的事件是否一致 | 真实道路场景下的长尾情况 |

**素材是合成的卡通驾驶舱，不能替代真实数据集。** 真实人脸/人体检测器在这段视频上大概率检不到目标，
因此它验证的是**告警链路与时序逻辑**，不是感知精度。感知精度评测需要真实标注数据集
（DMD Driver Monitoring Dataset、StateFarm 分心驾驶、AUC Distracted Driver 等），
甲方定型后应当在真实数据上重做这套评测。

这个区分必须在向甲方汇报时说清楚，否则合成素材上的漂亮数字会造成误导。

## 场景脚本

`scenario_a` 共 55 秒 @15fps，标注 4 段违规 + 9 个干扰项：

| 违规区间 | 时间 |
|---|---|
| 驾驶员未系安全带 | 2–14s（发车时未系，12 秒后系上） |
| 乘客未系安全带 | 6–52s（副驾全程未系） |
| 疲劳（持续闭眼） | 20–34s |
| 使用手机 | 40–48s |

**干扰项**（正确的系统不应对它们告警）：6 次正常眨眼（0.15–0.2 秒）、3 次短暂低头看仪表（0.5–0.7 秒）。
这两类动作正是现场误报的主要来源——把它们放进素材，是为了让「防误报做没做到位」变成可测量的事实，
而不是各路线在文档里的自我声明。

## 用法

```bash
# 1. 生成素材（确定性的，视频不入库，用时重新生成）
python3 bench/make_clip.py --out bench/clips/scenario_a

# 2. 各路线跑这段视频，把事件写成 JSONL（每行一个 SafetyEvent.to_dict()）
#    事件里请带上 raw_signals["clip_t"] = 视频内相对秒，否则打分只能靠绝对时间戳推断

# 3. 打分
python3 bench/score.py --truth bench/clips/scenario_a_truth.json \
                       --events runs/mode_c_events.jsonl --label 模式C
```

输出示例：

```
检出率      4/4  (100%)
告警延迟    平均 2.80s / 最慢 4.30s
误报        5 次  (5.45 次/分钟)
  其中被干扰项骗到  眨眼 3 次 / 短暂低头 2 次
```

## 打分口径

- **检出**：告警落在标注区间内，或区间结束后 1 秒宽限内（确认逻辑本身有固有延迟）
- **告警延迟**：违规区间起点 → 该区间内首次告警。这是三条路线差异最大的指标，
  边缘侧本地推理与云端往返的差距会直接体现在这里
- **误报**：未能匹配到任何标注区间的告警。会进一步归因到是否被眨眼、短暂低头骗到
